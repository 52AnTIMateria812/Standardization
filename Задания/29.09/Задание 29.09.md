# Сравнение стандартов ЕСПД и применение к проекту

Материал сопоставляет ГОСТ 19.401-78, ГОСТ 19.402-78, ГОСТ 19.503-79 и ГОСТ 19.505-79 по вопросам запуска программы и действий при сбоях. Во второй части требования применены к проекту «Как привезли» на основе Telegram-бота и Telegram Mini App.

## 1. Различия документов

| Стандарт | Документ | Запуск программы | Аварийные ситуации |
|---|---|---|---|
| ГОСТ 19.401-78 | Текст программы | Запуск не рассматривает; документ оформляет текст программы | Не рассматривает |
| ГОСТ 19.402-78 | Описание программы | Раздел «Вызов и загрузка» описывает способ вызова и входные точки | Отдельный раздел не выделен |
| ГОСТ 19.503-79 | Руководство системного программиста | Описывает настройку и проверку программы | Предусматривает сообщения системному программисту |
| ГОСТ 19.505-79 | Руководство оператора | В разделе «Выполнение программы» описываются загрузка, запуск, работа и завершение | Сбои и повторный запуск рассматриваются через сообщения оператору |

### 1.1 ГОСТ 19.401-78

Документ предназначен для представления исходного, промежуточного или машинного текста программы с комментариями о структуре и назначении. Инструкции оператору по запуску и восстановлению после отказов к нему не относятся.

### 1.2 ГОСТ 19.402-78

«Описание программы» включает общие сведения, назначение, логическую структуру, используемые технические средства, входные и выходные данные. Раздел «Вызов и загрузка» описывает запуск и точки входа, но не заменяет подробную инструкцию пользователя.

### 1.3 ГОСТ 19.503-79

«Руководство системного программиста» описывает устройство программы, её настройку и проверку, дополнительные возможности и сообщения системному программисту. Обычный запуск пользователем и подробные действия при авариях не являются его основной задачей.

### 1.4 ГОСТ 19.505-79

«Руководство оператора» подходит для повседневной работы. В нём описываются последовательность загрузки, запуска и завершения программы, сообщения и действия оператора при сбоях. В исходном документе аварийные случаи выделены отдельно для удобства, хотя соответствующая информация относится к сообщениям оператору.

## 2. Применение к проекту «Как вы это привезли?»

### 2.1 Назначение

Telegram-бот проводит пользователя через начальную настройку, показывает меню, принимает отзывы и заказы. Mini App позволяет просматривать каталог, находить товары, добавлять их в корзину, применять промокоды и передавать заказ боту.

### 2.2 Условия выполнения

- Python 3.10 или новее.
- Зависимости проекта из `requirements.txt`.
- Установленный Telegram.
- Публичный HTTPS-адрес для Mini App.
- Переменные окружения `BOT_TOKEN`, `ADMIN_ID` и `WEBAPP_URL`.

Токен и идентификатор администратора нельзя хранить в Git-репозитории. Если токен уже оказался опубликован, его следует отозвать через BotFather и заменить.

### 2.3 Запуск

**Mini App:** файлы размещаются в корне проекта: `index.html`, `style.css`, `app.js`, `products.json` и каталог `img/`. Для локальной проверки из корневой папки выполняется:

```bash
python3 -m http.server 8080
```

Для работы внутри Telegram приложение требуется опубликовать по HTTPS.

**Бот:** задать `BOT_TOKEN`, `ADMIN_ID` и `WEBAPP_URL`, установить зависимости и запустить:

```bash
python3 -m pip install -r requirements.txt
python3 bot.py
```

После старта отправить боту `/start`, выбрать город и статус клиента, затем использовать «Сделать заказ» и «Открыть каталог».

### 2.4 Работа программы

1. Пользователь выбирает товар и кладёт его в корзину.
2. В корзине указывает имя, телефон и адрес.
3. Нажимает «Оформить заказ».
4. Mini App передаёт сведения боту через `web_app_data`.
5. Бот подтверждает заказ пользователю и сообщает о нём администратору.

Для остановки бота или локального HTTP-сервера используется `Ctrl+C`.

### 2.5 Аварийные ситуации

| Ситуация | Рекомендуемое действие оператора |
|---|---|
| Mini App не открывается | Проверить HTTPS-адрес, `WEBAPP_URL` и доступность `index.html`; после исправления перезапустить бота. |
| Бот не запускается | Проверить `BOT_TOKEN`, `ADMIN_ID`, версию Python и установку библиотек. |
| Каталог пуст | Проверить доступность и синтаксис `products.json`. |
| Не загружается изображение | Сверить путь в поле `image` и наличие файла в `img/`. |
| Заказ не попал в бот | Проверить запуск Mini App через Telegram и работу polling-процесса, затем повторить заказ. |
| Заказ не дошёл администратору | Проверить `ADMIN_ID`, права бота и журнал работы. |
| Сбой питания или оборудования | Восстановить окружение, проверить HTTPS и повторно запустить `python3 bot.py`; незавершённый заказ не считать подтверждённым без уведомления администратора. |
| Утёк токен или данные заказа | Отозвать токен через BotFather, выпустить новый, обновить окружение; персональные сведения не публиковать в GitHub, issue или открытых логах. |

### 2.6 Сообщения оператору

- «Ничего не найдено» — изменить запрос или категорию.
- «Корзина пуста» — добавить товар.
- «Некорректное имя, номер телефона или адрес» — исправить указанное поле.
- «Промокод применён» — продолжить оформление.
- «Промокод не найден» — проверить ввод.
- «Ваш заказ принят» — дождаться уведомления администратора.
